KDS Terminologie-Fahrplan

Welche ValueSets des MII Kerndatensatzes ändern sich mit einem SNOMED-CT- oder LOINC-Release, und was ist zu tun?
Prototyp. Grundlage ist ein Vergleich der ValueSet-Expansionen auf dem MII-Terminologieserver. Releases, die dort noch nicht vorliegen, erscheinen als ausstehende Spalte.
Legende und Lesehilfe
Farbe der Strecke = was mit dem Inhalt des ValueSets zwischen zwei Releases passiert ist
  • unverändert
  • nur neue Codes (additiv)
  • Anzeigetexte geändert
  • Codes entfallen: aus dem Filter gefallen oder nicht mehr im Release (ohne Inaktiv-Status)
  • Codes inaktiviert oder Filter-Anker inaktiv (breaking)
  • gestrichelt: ValueSet ist gepinnt, Änderung gilt erst nach dem Pin-Wechsel
Symbole
  • Station = Stand des ValueSets unter einem Release; Größe = Anzahl Mitglieder (log.)
  • Umsteigebahnhof = inaktivierte Codes; farbig gefüllt
  • senkrechte Linie = Stand des Ballots (im Package gepinnte Version)
  • Verbindung zwischen Lanes = derselbe Code trifft mehrere ValueSets
  • graue Spalte / Station = Release noch nicht auf dem Server
Navigation
  • 1. In der Übersicht eine Zelle oder unten ein Modul wählen.
  • 2. Code-System oben über dem Plan umschalten.
  • 3. Strecke, Station oder ValueSet-Name anklicken, Details erscheinen rechts.
  • 4. Code-Suche findet einen Code in allen Änderungslisten.

Übersicht: Module × Releases

Zelle = schlimmste Änderung im Modul, Zahl = betroffene ValueSets von allen beobachteten. Klick öffnet den Plan.
